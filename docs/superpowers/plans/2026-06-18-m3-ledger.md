# M3 — Ledger (E4) Implementation Plan · gate NFR-01

> JIT bite-sized TDD plan for milestone M3 in `../../../technical-arch-impl-plans/04-implementation-plan.md` §3.
> Executed inline (TDD per chunk: red → green → verify → log). FINAL specs win on conflict (no-fork).

**Goal:** Build the Ledger — the hot Redis tier (hold-inclusive spend windows, reserved holds,
grant-dedup NX, QUOTED-time window snapshot) and the cold Postgres tier (append-only double-entry
`spend_events`/`allocation_events` + `payment_events` audit, dual timestamps), so Enforcement (M5)
can reserve against a real cap and settlement records balanced, durable accounting.

**Architecture:** Hot path writes Redis only (reserve via Lua, atomic across keys). Cold tier is
append-only and written async from SETTLED (fail-open record band). Every event carries dual
timestamps. NFR-01 (dual timestamps) is satisfied by construction here.

**Tech Stack:** ioredis + Lua (`EVAL`/`defineCommand`) · pg · Vitest + Testcontainers.

## Canonical behaviors (cited; adopt verbatim)
- Double-entry, two balanced rows, append-only, never updated in place: `engine-specs-FINAL.md:165-166`
- Two ledgers `spend_events` (agent→external) + `allocation_events` (treasury→agent): `engine-specs-FINAL.md:147,152`
- `payment_events` audit columns (agent, rail, service_domain, requested vs consumed, policy_version, result, reason_code, state, ts): `policy-engine-FINAL.md:228-231`

- Reserve is one atomic Lua across multiple keys: `engine-specs-FINAL.md:128`
- Window snapshot at QUOTED (floor boundaries; deduct into SNAPSHOTTED window, not current): `policy-engine-FINAL.md:241-249`
- Dual timestamps `enforcement_timestamp` (QUOTED-time, all policy math) + `settlement_timestamp` (on-chain SETTLED, accounting): `engine-specs-FINAL.md:151`
- Hold converts in place on SETTLED, dropped only on FAILED_TERMINAL/EXPIRED: `engine-specs-FINAL.md:153`
- Cold writes async from SETTLED via transactional outbox, never on hot path, never raw signature: `engine-specs-FINAL.md:156`, `policy-engine-FINAL.md:228-231`

## Implementation choices where the spec is SILENT (flagged, not spec claims)
- **ZSET encoding:** per-window ZSET `agent:{id}:spend:{w}`, member = `paymentId`, score = enforcement timestamp (the QUOTED snapshot). Amounts in a companion hash `agent:{id}:spend_amounts` (paymentId → base-unit string). Window sum = `ZRANGEBYSCORE(spend:{w}, minTs, +inf)` → `HMGET` amounts → sum bigints. Keeps the locked keyspace (`spendWindow(agentId, w)`) + SPIKE-06 intact.
- **Outbox:** Phase-1 writes cold events directly inside the settle transaction (synchronous append in the RECORD band). The full `audit_outbox` + DLQ worker (BUG-22/38) is a robustness layer deferred; the dual-timestamp + append-only + double-entry invariants are met now. Logged as a Phase-1 simplification.
- **Reserve mirrors holds into both the per-window ZSET (cap math) and `agent:{id}:reserved` (custody spendable subtrahend)** — same hold, two consumers — which is exactly why reserve must be one atomic Lua.

## Acceptance (doc 04 §3 M3 + gate NFR-01)

balanced rows; every event carries both timestamps; reads are append-only (no in-place update path
exists). Contracts: C-3 (quote consumed), C-5 (events). NFR-01 cleared.
